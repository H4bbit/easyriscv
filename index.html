EasyRISC-V Terminal

Bare-metal RV32I playground in the browser. Inspired by easy6502 by Nick Morgan (CC BY 4.0). No toolchain, no server: the assembler and CPU are riscv.js.

Playground · Memory map · Assembler notes

Playground

Click Assemble, then Run. Tick Debugger for single-stepping, Monitor for a hex view. Keys WASD feed the 0xFF port (Snake).

Notes: Address 0xFE reads a new random byte on every load (lbu + andi mask). Address 0xFF reads the ASCII code of the last key pressed (0 = none). Addresses 0x200 to 0x5FF map to the 32x32 screen pixels (1 byte/pixel). Only the low nibble shows: colours are $0 Black, $1 White, $2 Red, $3 Cyan, $4 Purple, $5 Green, $6 Blue, $7 Yellow, $8 Orange, $9 Brown, $a Light red, $b Dark grey, $c Grey, $d Light green, $e Light blue, $f Light grey. Stores to 0x1000 print the low byte as a character (print-char port). Code lives at 0x600. Halt is a jump to self: j . (jal x0, 0). There are no syscalls here: ecall/ebreak exist in hardware but the lessons never use them. jal/jalr never touch the stack: ra is just a register, unlike 6502 JSR/RTS which push the PC in hardware.

Memory map

0x000-0x0FF  RAM / zero-page (variables, game state)
0x100-0x1FF  stack (grows down from 0x1FC)
0x200-0x5FF  framebuffer 32x32, 1 byte/pixel (low nibble = colour)
0x600-...    code (PC starts at 0x600)
0xFE/0xFF    MMIO random / last-key (intercepted on LOAD)
0x1000       MMIO print-char port (intercepted on STORE)

Assembler notes

  • Two passes, like the easy6502 assembler: define/.equ, labels, then code at 0x600. Fixed 32-bit words, so every instruction is 4 bytes except li with a large immediate (lui + addi, 8 bytes).
  • Canonical first, pseudo right after: li/mv/nop/j/jal/jr/ret, not/neg/seqz/snez/sltz/sgtz, beqz/bnez/blez/bgez/bltz/bgtz, bgt/ble/bgtu/bleu all assemble to their canonical encodings. Disassembly shows the same folds as vm.c (li/mv/beqz/bnez).
  • li takes a number or symbol only: a label address in li is out of scope (that is what la is for, and la/call/tail stay out of scope in the fixed 0x600 model).
  • Comments are // and ;. Numbers are decimal, 0x hex, $ hex, % binary. .byte/.word emit raw data.
